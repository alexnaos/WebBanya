## 🔴 Критические проблемы (нужно исправить срочно)

### 1. Запись некорректных температур в БД
**Файл:** `src/sensors.cpp` строки 31-37

**Проблема:** При отключении датчика DS18B20 функция `getTempC()` возвращает `DEVICE_DISCONNECTED_C` (-127°C). Это значение записывается в базу данных и публикуется через MQTT, показывая неверные температуры.

**Исправление:**
```cpp
// В sensiors.cpp, в функции handleSensors()
if (t1 != DEVICE_DISCONNECTED_C) {
    temp1 = t1;
    db[kk::tmp1] = temp1;  // Добавить проверку!
}
if (t2 != DEVICE_DISCONNECTED_C) {
    temp2 = t2;
    db[kk::tmp2] = temp2;  // Добавить проверку!
}
```

---

### 2. Занесение `GyverOLED` в зависимостих без необходимости
**Файл:** `platformio.ini` строка 109 (в `lib_deps`)

**Проблема:** Указан `gyverlibs/GyverOLED@^1.6.4`, но в коде используется `Adafruit SSD1306`. Библиотека не используется, но занимает место и время компиляции.

**Исправление:** Удалить `gyverlibs/GyverOLED` из `lib_deps` в `platformio.ini`.

---

### 3. Три вызова `setStampZone(3)`
**Файл:** `src/main.cpp` строки 81, 103, и, вероятно, 137

**Проблема:** Вызов часового пояса трижды в коде. Не критично, но некрасиво и может вызывать путаницу.

**Исправление:** Оставить один вызов в `setup()` после всех инициализаций.

## 🟡 Серьезные проблемы

### 4. Магические числа разбросаны по коду
**Файлы:** все `.cpp` файлы

**Числа:** `200` (размер логгера), `1023` (PWM max), `100`/`500`/`2000` (таймеры), `15000` (таймаут WiFi).

**Исправление:** Вынести все в `src/config.h`:
```cpp
#define LOGGER_SIZE 200
#define TEMP_UPDATE_MS 1000
#define OLED_UPDATE_MS 500
#define MQTT_SEND_MS 2000
#define WIFI_TIMEOUT_MS 15000
```

---

### 5. Нет watchdog-таймера
**Проблема:** ESP8266 может зависнуть silently, особенно при fluctuations WiFi или OTA.

**Исправление:** Добавить в `src/main.cpp` в `loop()`:
```cpp
void loop() {
    ESP.wdtFeed(); // предотвратить перезагрузку сторожевого таймера
    // ... остальной код
}
```

---

### 6. Последовательность инициализации WiFi
**Проблема:** `WiFi.mode(WIFI_STA)` устанавливается после `wifiMulti.addAP()`.

**Исправление:** Переместить `WiFi.mode(WIFI_STA)` перед вызовом `wifiMulti.addAP()` в `src/main.cpp`.

---

## 🟠 Проблемы средней важности

### 7. Хаотичная структура проекта
**Проблема:** Зоны ответственности перекрываются:
- `config.h` — конфиг + глобальные переменные + функции
- `sensors.cpp` — датчики + OLED + update-функции
- `main.cpp` — setup/loop + MQTT + WiFi + PWM + OTA

**Рекомендация:** Рефакторинг к модулям (оценивается как улучшение, но не критическое).

---

### 8. Статические переменные `tmr` и переполнение `millis()`
**Проблема:** Через ~50 дней `millis()` переполняется. Статические переменные `tmr` сбрасываются, что может вызвать двойной вызов таймера.

**Nuance:** Шаблон `if (millis() - tmr >= interval)` корректно обрабатывает переполнение благодаря беззнаковой арифметике. Главное — не сбрасывать `tmr` в 0 в других местах.

---

### 9. Блокирующий цикл ожидания WiFi
**Файл:** `src/wifi_manager.cpp` и `src/main.cpp`

**Проблема:** Если оба WiFi-точки недоступны, ESP8266 висит вечно.

**Исправление:** Убедиться, что `wifi_manager.cpp` использует неблокирующий подход с таймаутом (проверяется, что уже есть `WIFI_TIMEOUT_MS`).
